# Mabna simulator (offline development)

A local SQL Server 2019 container with a database named `TotalSystem` that has
the captured Mabna **schema** and **synthetic demonstration data**. It exists so
the accounting connector (spec 002) can be built and tested offline. It never
connects to any company server.

- **All data is synthetic.** The seed is generated by `gen_seed.py` from a fixed
  random seed. No real row is read, stored or embedded anywhere.
- **FR-02:** anything containing real table or column names lives only in
  `deploy/mabna-sim/generated/` (gitignored). Only generic tooling is tracked.

## Prerequisites

- Docker Desktop. On Apple Silicon enable *Settings > General > Use Rosetta for
  x86_64/amd64 emulation* and give the VM >= 4 GB RAM (the image is x86-64
  only; Rosetta is not officially supported by Microsoft).
- Fallback if 2019 misbehaves: switch both images in
  `deploy/docker-compose.mabna-sim.yml` to `mssql/server:2022-latest` and set
  compatibility level 150 (already done by `generated/00-database.sql`).
- In `deploy/.env` set `MABNA_SIM_SA_PASSWORD` and `MABNA_SIM_RO_PASSWORD`
  (see `deploy/.env.example`; SQL Server complexity rules apply).

## Start / stop / reset

```bash
docker compose -f deploy/docker-compose.mabna-sim.yml up -d       # start + init (first run builds the DB)
docker compose -f deploy/docker-compose.mabna-sim.yml logs mabna-sim-init
docker compose -f deploy/docker-compose.mabna-sim.yml down        # stop, keep data
docker compose -f deploy/docker-compose.mabna-sim.yml down -v     # reset: delete the volume
```

Listens on `127.0.0.1:14330` (`MABNA_SIM_PORT`). Connection string for the
connector: `Server=127.0.0.1,14330;Database=TotalSystem;User Id=zharfa_ro;Password=...;TrustServerCertificate=True`.

The one-shot `mabna-sim-init` container runs `generated/*.sql` and `init/*.sql`
merged in filename order: `00-database`, `01-schema`, `02-seed` (generated),
`90-readonly-login` (tracked). If `TotalSystem` already exists only `9*` files
are re-run, so `up` is idempotent; use `down -v` to rebuild.

## Read-only login

`init/90-readonly-login.sql` creates `zharfa_ro`: member of `db_datareader`,
with `DENY INSERT, UPDATE, DELETE, ALTER, EXECUTE` (plus CREATE TABLE/VIEW/
PROCEDURE), matching production rights (FR-03). Run the connector as
`zharfa_ro`, never as `sa`.

## Regenerate from a real schema capture

1. On-site run `scratch/mabna-schema-capture.sql` (sqlcmd, `-s"|" -W`), copy the
   output text file to the dev machine.
2. `python3 deploy/mabna-sim/gen_schema.py path/to/capture.txt` writes
   `generated/00-database.sql` (collation preserved) and `generated/01-schema.sql`
   (tables, types, nullability, identity, defaults, PKs, FKs). Views, indexes and
   check constraints are not recreated; FKs to tables outside the capture are skipped.
3. Copy `example/seed-map.example.json` to `generated/map.json`, set real table
   and column names / status codes, then
   `python3 deploy/mabna-sim/gen_seed.py --map deploy/mabna-sim/generated/map.json`.
4. `docker compose -f deploy/docker-compose.mabna-sim.yml down -v && ... up -d`.

Try the toolchain without a capture:
`python3 deploy/mabna-sim/gen_schema.py deploy/mabna-sim/example/schema-capture.example.txt`
then `python3 deploy/mabna-sim/gen_seed.py` (made-up `SimInvoice` etc.).
The example is **PENDING real capture**; replace it before relying on the sim.

## Seed edge cases

Jalali dates as text `yyyy/mm/dd` (some with Persian digits) and numeric
`yyyymmdd` side by side; Arabic ي/ك mixed with Persian ی/ک; normal, cancelled
and returned invoices (both sign conventions); uncleared, cleared and bounced
cheques; NULL dates, notes and phones.

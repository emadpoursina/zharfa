## Hard rules for every task

- Authorization is decided on the server only. Every controller action carries `[Authorize(Policy = Permissions.X)]` (or explicit `[AllowAnonymous]` for login/logout, or plain `[Authorize]` for `me`, `change-password`, `system/status`). The SPA hiding a tab is cosmetic.
- Never pass a password, password hash, cookie, session token, provider key, connection string or report row/figure to `IAuditLogger`, to `ILogger`, or into any API response. Audit details are built only with `AuditDetail` and always go through `RedactionHelper.Scrub`.
- An audit write failure never changes the outcome of the audited action (`AuditLogger` already swallows it); a 403 stays a 403.
- Validation and notices read the synced copy (`mabna.*` in PostgreSQL) through the existing `NpgsqlDataSource` only; they never `INSERT/UPDATE/DELETE` any `mabna.*` row and never query Mabna. Flags never change any report figure (FR-026).
- No user text reaches SQL: every value is an `NpgsqlParameter`; optional filters use the `(@p::type IS NULL OR …)` pattern already used in `ReportSql`.
- Never commit real Mabna table/column names, rows or totals; the simulator tool is generic and reads names from the source map; committed examples use `Sim*` names.
- Persian-first: RTL, Jalali dates/times with Persian digits (reuse `SyncTimeText.Jalali`, `JalaliDate`), Persian messages copied exactly from contracts/api.md (server messages in §0–§5, UI strings by id `S-…` in §9), every new response carries `dataLabel`.
- New type or property names in namespace `Zharfa.Api.Purchasing.Reports` must not contain `balance`, `payment`, `debt`, `credit` or `paid` (`NoVendorFinancialsTests` scans that namespace).
- Do not commit, push, or run `npm install` / `dotnet test`; the tester runs `.ainative/project.yaml` `validation_commands`.
